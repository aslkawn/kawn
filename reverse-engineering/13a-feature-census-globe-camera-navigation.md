# 13a. Feature census and gap audit: globe, camera and navigation

## Purpose and method

Purpose: an independent list of every behaviour in the studied application's globe, camera and navigation domain, explained at technique level so a clean-room team can rebuild it, and a comparison against our existing notes (00 to 12). Domain covered: zooming into a location (wheel, pinch, keys, voice, fly-to, landmark framing, altitude limits, zoom clamps), search and geocoding, the location tray, reset globe, tilt / north-up / orbit, startup camera, share-link restore, terrain and ground guard, basemap sources and switching, Google 3D tiles and Cesium ion, tile retry, the rendering governor and performance, celestial / atmosphere / sun lighting, clean UI and the status strip.

Method (enumeration was done from the source before the comparison with our notes): read the project README, change log, data-source note, current-state note and performance note; read the camera, location, search, map-source, share-link, render-governor, celestial-ring and ground-guard modules in full; read the UI controllers that bind the location tray, the top-centre camera buttons and the map-source chips; read the voice action schemas and the voice implementations of fly-to, relative zoom, reset and camera verbs; read the page templates for the dock, top-centre cluster, Display panel and loader; and used the colocated test titles to confirm intended behaviour. GitNexus was run for two concept queries (fly to a searched location; trace from the search flight to the landmark flight). Its concept search returned unrelated results (CCTV and messaging helpers), so the flows below come from reading the source directly once GitNexus had confirmed which modules own the navigation functions; this is a limit of the index, not of the application.

Reading guide: "Documented in" is the existing note and section, or THIN (present but missing numbers or rules) or MISSING. "Kawn verdict" is KEEP, ADAPT, LATER or SKIP. "UAE" is relevance to Dubai, Abu Dhabi and the Gulf. Numbers are from the source unless marked UNVERIFIED. The studied application is built on a general-purpose open-source 3D globe engine (Cesium); where the text says "the engine" it means that library's built-in behaviour.

Headline finding: our existing notes (especially 06, 05, 01 and 02) already cover this domain very well. The gaps are therefore narrow but real: the exact rules that make a search land in the right place (the administrative-box sanity gate, the geocoder chain's internal behaviour, the nearby-place recovery, the building-framing maths), the grammar of typed coordinates, the numbers of the voice relative zoom, the first-frame viewer settings, and several clarifications (there is no keyboard zoom, no day/night shading, the viewport box is fitted by the engine, hash writes are suppressed during restore).

## 1. How "zoom into a location" works, end to end

This section follows one request from the moment the user acts to the moment the camera settles. There are four entry doors; they all converge on one of two flight recipes.

### 1.1 The four entry doors

1. **A city pill or a landmark pill/key in the location tray.** Instant, no network. The app holds nine curated cities (Austin, San Francisco, New York, Tokyo, London, Paris, Dubai, Washington DC, Tallinn); each has a ground elevation, a rectangular view box and exactly five landmarks, each with its own hand-tuned camera distance, pitch, heading and an estimated landmark height. The five landmarks are bound to the keys Q, W, E, R, T, but the keys only act while that city's landmark row is open and the keyboard focus is not inside a text field or selector.
2. **Typed search in the tray's search box.** Needs a geocoder; asynchronous. This is the long path and is explained in 1.3 to 1.6.
3. **Voice or tool request to fly to a place.** One tool accepts any one of: a preset city, a free-text name, a latitude and longitude pair, or a reference to a contact the assistant has just listed (the contact is relocated at call time, because it moves). Optional extras: "close" or "overview" framing; an explicit distance (the schema allows 100 m to 20,000 km and the handler clamps anything outside that band to the nearest limit); and "wait for arrival", which makes the tool reply only after the flight lands or is cancelled. A separate tool nudges zoom, and another returns to the globe.
4. **Reset globe** (top-centre button, Cockpit button, or the sentence "zoom out to a globe view"). Not a zoom to a place but a zoom out, described in NAV-32.

Mouse wheel, trackpad pinch and drag are not "zoom into a location": they are the engine's free-camera controls (NAV-01 to NAV-03) and they cancel any automatic move in progress.

### 1.2 Ownership check before anything moves

Every explicit destination first asks "who owns the camera?". If Cockpit (first-person aircraft) is active, the request is refused with a short message telling the user to exit Cockpit. Otherwise the app stamps a new "navigation generation" (a counter), cancels any pending arrival correction, releases every follow owner (tracked aircraft, military aircraft, satellite, vessel selection, space-mission camera, Contacts), stops orbit and camera verbs, cancels any flight in progress and clears any look-at lock. Typed searches are different: they stamp a generation at submit time but do NOT release anything, because the answer may never come; only when the geocode returns do they re-check that their generation is still the newest and that Cockpit is still off, and only then release and fly. A newer navigation (or a user gesture) therefore silently kills an older search, and the old "searched location" label stays on screen until a real arrival replaces it. (Documented in 06 s1.3.)

### 1.3 Typed search: the provider chain

The query goes to a chain of providers tried in order; the first one with a place wins and later ones are not asked:

1. **Decimal coordinates** (offline, exact). See NAV-10 for the grammar.
2. **Bundled names** (offline, exact): the nine city ids and names and all 45 landmark names, compared after case, accent and punctuation folding. Only whole-name matches count, so a bundled name never shadows a real geocoder for something that merely resembles it.
3. **The unqualified Alps** (offline): "Alps" or "the Alps (Mountains)" returns the bundled range outline's centre and bounding box, so it does not resolve to a same-named peak or shop.
4. **Google Geocoding**, only if a browser Google key exists; the current view is passed as a bounding-box bias.
5. **Photon** (public OpenStreetMap geocoder run by Komoot), keyless, biased to the view centre.
6. **The app's own proxy to OpenStreetMap's Nominatim**, last resort, one request per second server-side with a five-minute cache.

The whole chain has a 12-second budget. Answers that are definitive (a place, or a clean "nothing found") are cached for five minutes (30 seconds for "nothing"); a timeout or network failure is never cached, so a transient outage cannot be remembered as "no such place". The cache holds the most recent 64 queries per view-bias. Each place comes back with a position, a label, a list of Google-style "types", a flag meaning "exact, do not second-guess", and optionally a bounding box ("viewport"). Photon and Nominatim results are translated into the same shape, including the types, so the framing logic downstream is written once.

### 1.4 Rescue of a mis-read name (only for non-exact answers)

If the answer is not flagged exact, the app checks whether the user is looking at somewhere else. It finds the point under the screen centre (or, when the screen centre shows only sky, the point on the ground directly beneath the camera). If the geocoder returned nothing, or its answer lies more than 50 km from that point, it asks a Places text search (Google Places, so only if configured), biased to a 6 km circle around the view centre, and trusts the hit only if it lies within 8 km of the view centre. Example: "the Capitol" typed while hovering over Austin should be the Texas State Capitol, not the one in Washington. A near geocode is left alone. A typed coordinate or a bundled name is never overridden. Without a Google key this step quietly does nothing (UNVERIFIED whether the keyless path has any substitute; the code asks the same place-search service, which only the Google adapter implements).

### 1.5 Choosing a framing mode from the place type

The "types" list decides the mode:

| Place type | Mode | What happens |
|---|---|---|
| country, state/province, county-level | region overview | Fly to the place's whole bounding box (see 1.6) |
| city/town | city overview | Fly to the city's bounding box, after the sanity gate |
| district, neighbourhood, postal code | neighbourhood close | Close landmark framing at the default 250 m, but with no building-outline lookup (that is done only for precise places) |
| street, intersection | street corridor | Fit the street's box; if no usable box, fall back to a 900 m range |
| park, natural feature, campus, university, airport, stadium, amusement park, zoo, cemetery, mall | area overview | Fit the box (with the natural-region swath rule for huge boxes); if no box, 1,400 m range |
| anything else (building, address, point of interest, bare coordinate) | precise place | Close landmark framing, default range 250 m |

An explicit distance from the caller (voice) skips box fitting and uses that range with landmark framing. An explicit "close" request forces landmark framing even for areas; an explicit "overview" request forces box fitting even for precise places and also switches off the sanity gate (the user has said exactly what they want).

### 1.6 The three flight recipes

**A. Box fit (regions, cities, areas, streets).** The box is padded by 12 % of its height and 12 % of its width, with a minimum pad of 0.05 degrees each way, and clamped to 89.9 degrees latitude. Width is measured the short way round the planet so a box that crosses the date line (Alaska, Fiji, a Pacific metro) is not read as 340 degrees wide; padded edges are wrapped back into range, and a padded width of 360 degrees or more becomes the whole longitude range. The engine then flies the camera to a rectangle: it chooses the altitude itself so the rectangle fills the view, looking straight down with north up. Default duration is 3 seconds for UI searches and 2.2 seconds for voice, cubic ease in and out. The "camera end transform" is reset to the world frame so a previous look-at lock cannot bend the flight.

**B. Sanity gate before box fit (cities and regions only, not countries, not explicit overviews).** Administrative boxes can be much bigger than the place anyone means: "Tokyo" is a whole prefecture that includes islands about 1,000 km out to sea, so its box centre is open Pacific. Rule: if the box diagonal exceeds 300 km AND the geocoded anchor point sits further than 15 % of the diagonal from the box centre, the box is replaced by a 40 km by 40 km square around the anchor (the same scale as the hand-made city pills). Measured on live data: Tokyo ratio 0.40 and Hawaii 0.46 are gated; Nunavut 0.10, Alaska 0.09, Japan 0.09, Texas 0.05, California 0.04 keep their boxes, so the 0.15 line sits in a 2.2x gap. Countries are deliberately exempt even though France (0.39), Portugal (0.38), Ecuador (0.30), Chile (0.26) and Spain (0.22) show the same flaw from overseas territories; the authors flagged it and left it.

**C. Natural-region swath.** A natural feature whose box diagonal exceeds 400 km (Rockies about 2,700 km, Alps about 880 km; Lake Tahoe at about 50 km stays below) would put the camera in space. Instead the camera frames a representative oblique swath: centred on the box centre, 280 km range, pitch -35 degrees, heading north for a feature that is taller than wide and east for one that is wider than tall, so the range recedes toward the horizon along its long axis.

**D. Landmark framing (precise places, explicit ranges, coordinates).** This is the recipe behind pills, coordinates and buildings.
1. *Ground height.* The aim point's height is the first of: the engine's sampled terrain height if above zero; the shared ground-floor service's cached value (a coarse elevation lookup, NAV-39); the city's curated elevation; zero. The next nearby cell is warmed in the background. For a searched place the app waits (bounded) for the ground-floor lookup before framing, so an uncurated hill town or a Denver coordinate is not framed against sea level.
2. *Building outline (precise places only).* The app asks OpenStreetMap (through the Overpass query service, or the source adapter in use) for buildings, man-made structures and tourist attractions within 180 m of the geocoded point, and scores candidates: 1,000 points per query word (words longer than 2 letters) shared with the feature's names, plus 500 if the point is inside the footprint, minus the distance in metres. Footprints under 2 m in either dimension are ignored. Height is the tagged height, else 80 % of the longer side clamped to 12 to 80 m. If the outline source is unavailable the flight still happens and the user sees "Detailed outline unavailable".
3. *Range.* With an outline: a bounding sphere of half the diagonal of the building box times 1.18; the camera range is the larger of the range that makes that sphere occupy 57 % of the limiting viewport dimension (using the real field of view and aspect ratio, times 1.05) and 1.35 times the radius. Without an outline: the caller's range (250 m default; each preset landmark carries its own).
4. *Pitch.* Preset landmarks use their own. Searched buildings use their shape: very tall and thin (height over footprint at least 2.5) -12 degrees; tall (at least 1.2) -22; squat (at most 0.35) -45; otherwise -32; no outline at all -25. Searched heading is 30 degrees; voice coordinates use heading 0 and pitch -35.
5. *Aim.* The aim point is the ground height plus half the building height (or plus 30 m for an unknown landmark, 0 for a bare coordinate).
6. *Flight.* A smooth flight to a bounding sphere at the requested heading, pitch and range, 3.0 seconds by default (2.2 s for voice), then a final look-at lock so the target is exactly centred, then the lock is released so manual control works again.
7. *Settle (ground guard).* Because tiles had not streamed in when framing was computed, a guard then measures the rendered surface under the target and under the camera, retrying up to 8 times at 600 ms, and lifts the camera straight up with a 0.9 s ease if the eye is within 120 m of the surface (ignoring deficits of 2 m or less). Any key press, pointer press or wheel on the canvas, tracking start, direct camera call, or newer arrival cancels it. (Documented in 06 s1.7.)

### 1.7 What the user sees while it happens

The search box gains a "searching" look; a toast says "Location not found" or "Search failed" on the two failures; the tray's collapsed two-line readout switches to the searched address (first segment as the place, the rest as context, or "Searched location" for a one-segment answer) and the previous city highlight and landmark row are cleared; the box closes and clears when the flight starts or the search settles. Moving between two different preset cities is a "world jump": the detection overlay is suspended and the road-traffic simulation paused until arrival (or a 5.2 s watchdog) so labels do not smear across continents. A preset city always wins over a searched label in the readout.

## 3. Gaps found, with the missing behaviour written out

Every item below is either MISSING from or THIN in notes 00 to 12. Each is written as testable rules so it can be added to a Kawn spec today.

**G1. Administrative-box sanity gate (MISSING).** When a city or state/province/county search returns a box, measure its diagonal in km (short-way-round longitude, 111.32 km per degree of latitude). If the diagonal is 300 km or less, use the box. Otherwise measure the distance from the geocoder's own anchor point to the box centre; if that distance is more than 15 % of the diagonal, discard the box and use a 40 km square around the anchor (capped at 89.9 degrees latitude, longitude wrapped). Countries are exempt; explicit "overview" requests skip the gate. Acceptance: "Tokyo" must end within about 50 km of Tokyo Station, never over the open Pacific. UAE implication: emirate-level boxes (Abu Dhabi emirate includes large desert and offshore islands) are very likely to trip the same flaw; Kawn should test "Abu Dhabi", "Dubai" and "Sharjah" and keep the rule.

**G2. Coordinate grammar (THIN).** Accept exactly two decimal components. Separators: a comma, a semicolon, or whitespace (whitespace splitting only where the next token starts a number or a hemisphere letter). A component may carry one hemisphere letter N, S, E or W before or after the number, with an optional degree sign; a leading sign and a letter together are refused. With no letters: latitude first. With letters: any order, as long as the two letters name different axes (so "W 55.27, N 25.19" is accepted). Refuse: out-of-range values (latitude beyond 90, longitude beyond 180), more or fewer than two components, trailing text, degrees-minutes-seconds, UTM or MGRS, plus codes. Result label is formatted with four decimals and hemisphere letters; the result is "exact" and gets a box of 0.03 degrees across (about 3 km), so it is framed as a precise place unless the caller passes a range.

**G3. Photon adapter behaviour (THIN).** Ask for five candidates (proximity bias reorders them, so the wanted name may not be first). Pass one is biased to the centre of the current view box (only the centre is sent; Photon takes a point, not a box) and accepts only a candidate whose folded name equals the query or begins with it. Pass two is unbiased: choose the first candidate whose folded name equals or begins with the first comma-separated part of the query; else the first that contains it; else the first returned. Folding removes accents, lowercases and collapses non-alphanumerics. Any candidate that is not a valid point makes the whole response invalid. Each request has a 6 s timeout. Hits are memoised for 5 minutes, definitive misses for 30 s, 64 entries; a failed request is not memoised. Type inference is by OpenStreetMap tag first (a table of park, stadium, university, airport, mall, zoo, theme park, cemetery, forest, region, suburb tags; town squares are deliberately precise; any natural, water, waterway or landuse key is a natural feature; highway is a street) and only then by Photon's coarse class (country, state, county, city, district, locality, street). The reason for the tag-first rule: a lake or park without an area type framed at building range (the camera ended 26 m above water), while treating a town square as a locality framed Times Square like a city. Label is the name plus district, city, state, country (duplicates dropped). Box order from Photon is west, north, east, south; a box with west greater than east (date-line wrap) is dropped and the place is framed at its point.

**G4. Nearby-place recovery (THIN).** Precondition: the answer is not exact and a Places service is available. Trigger: no geocode, or geocode more than 50 km from the view centre. Query: text search biased to a 6 km circle around the view centre (the view centre is a screen-centre surface pick, or the point beneath the camera when nothing is picked). Accept only a hit within 8 km of the view centre; otherwise keep the geocode. Replaces the point, label, types and box with the hit's. Cached per query and rounded centre.

**G5. Building framing maths (THIN).** See s1.6 D steps 2 to 5: candidate scoring (1,000 per shared query word longer than 2 letters, +500 if inside, minus metres of distance), minimum footprint 2 m, height default rule (tag, else 0.8 x longer side clamped 12 to 80 m), bounding radius = half the 3-D diagonal x 1.18, camera range = max(range that makes the sphere fill 57 % of the limiting field of view x 1.05, radius x 1.35), pitch table by height-to-footprint ratio (>= 2.5: -12; >= 1.2: -22; <= 0.35: -45; else -32; no outline: -25), heading 30, aim height = ground + half building height. Outline lookup asks for buildings, man-made structures and tourist attractions within 180 m; if the source reports "unavailable" the flight proceeds and the UI says "Detailed outline unavailable".

**G6. Voice relative zoom numbers (THIN).** little = 25 %, medium = 55 %, a lot = 100 % of the current distance to the view target (surface pick at screen centre; fallback: camera height, minimum 100 m). Zoom in: step at least 20 m, never closer than 25 m to the target, fails with "Camera is already at the minimum target distance" when no room. Zoom out: step at least 50 m. Cancels any flight first. Success only if the camera actually moved at least 0.5 m; otherwise returns "Cesium camera position did not change". Reply: requested metres, actual metres, before and after height.

**G7. Wait-for-arrival and contact reference (THIN).** With the wait flag the tool reports progress ("fly") and returns only when the flight completes (arrived) or is cancelled (cancelled, not an error). A reference to a listed contact is resolved to the contact's current coordinates at call time; if the contact is no longer loaded the tool returns "no longer loaded" rather than flying to a stale position. A navigation refused by Cockpit returns a cancelled result with the label.

**G8. No keyboard zoom or pan (MISSING statement).** The globe has no keyboard camera controls. Q/W/E/R/T act only while a city's landmark row is open and focus is outside text fields; 1-7 looks, H HUD, O orbit, V clean view, F layers, D detection, C camera panel, backtick FPS, Escape. Kawn should decide whether to add arrow/+/- keys for accessibility.

**G9. World jump scope (THIN).** The traffic and detection pause happens only when the user clicks a city or landmark pill AND a different preset city is already active. Searching across continents, voice flights, share-link restores and reset globe do not use the pill rule (reset begins its own jump). So a long typed-search flight does not suspend labels. Kawn can apply the rule on distance instead.

**G10. Box padding and date-line rules (THIN).** Pad = max(0.05 degrees, 12 % of the span) on each side; latitude clamped to +/-89.9; longitude span measured the short way; padded span of 360 degrees or more means the full longitude range; edges wrapped into range so a crossing box becomes an east-less-than-west rectangle. Reported centre uses the same short-way rule. Without these a 0.4-degree metro box straddling the date line frames 86.7 degrees of ocean.

**G11. Share-link restore subtleties (THIN).** Hash writes are suppressed while the initial restore is pending, so a recipient's first moves cannot overwrite the incoming link; the link needs finite latitude and longitude, else it is ignored entirely; restored lanes (visual, map, each panel) can be claimed by a later explicit action, which then wins; destroying the manager during its own flight cancels the owned navigation only if still current.

**G12. Tilt and north-up target (THIN).** The orbit target for tilt and north-up is: the tracked entity's displayed position if tracking (read without advancing the aircraft's own interpolation), else the surface pick at screen centre, else the terrain pick, else the ellipsoid pick. The new view is applied as a look-at about that target and then converted back to a free camera so no hidden transform remains (except when tracking, where the follower's own frame is restored).

**G13. UAE/Gulf coverage gaps (MISSING).** Only Dubai is a preset city (five landmarks); Abu Dhabi, Sharjah, Doha, Riyadh and the other emirates have none. The voice schema lists eight cities (no Tallinn) but a spoken or typed "Tallinn" still resolves to its preset through the free-text path. Arabic-script queries and bilingual labels are untested. Kawn should add Abu Dhabi (Burj Khalifa-class landmarks: Sheikh Zayed Grand Mosque, Etihad Towers, Louvre Abu Dhabi, Yas Island), Sharjah, Al Ain, and consider Arabic aliases in the bundled-name index.

**G14. Error and message catalogue for this domain (THIN).** "Exit cockpit to fly to a location/target" (refusal); "Location not found"; "Search failed"; "Detailed outline unavailable"; "Fly to a POI first" and the voice error "No active landmark to orbit"; "Camera is already at the minimum target distance"; "Cesium camera position did not change"; map messages "Esri Satellite is unavailable; using OSM", "Esri Satellite tile requests failed; using OSM", tailored key-requirement reasons; "Google 3D tiles unavailable" plus detail in the loader; tool errors for an unknown map source, unknown motion, missing direction, and a flight request with no place.

## 4. Corrections to existing docs

1. **06 s1.5 (typed search).** The description says countries/states/regions fly to the whole viewport and cities frame their viewport. Incomplete: (a) cities and states pass through the sanity gate in G1 (countries and explicit overviews do not); (b) neighbourhoods, districts and postal codes use close landmark framing at 250 m, not a box; (c) streets fit their box or fall back to 900 m; (d) areas fall back to 1,400 m with no box; (e) precise places look up the building outline. Add the table in s1.5 above.
2. **06 s1.5 ("Search bias follows the current view").** Provider-specific: Google receives the view's bounding box; Photon receives only the box centre as a point; the local proxy receives the box as a query parameter (whether the server uses it is UNVERIFIED). Bundled names and coordinates ignore bias.
3. **06 s1.5 and 01 s4.1 (inter-city jump).** The jump applies only to pill and landmark clicks when a different preset city was already active (not on first use, not from a searched location, not for typed or voice flights).
4. **08 (fly-to row, "preset city (8...)").** Add that the list excludes Tallinn but free text still reaches it; add that an explicit distance is clamped to 100 m to 20,000 km (not substituted), the 2.2 s duration, the wait-for-arrival option and its cancelled-versus-arrived result.
5. **08 (relative zoom row).** Add the 25/55/100 % fractions and minimum steps (G6); the note "cannot reach full-globe view" is a consequence of the fractions, not a rule.
6. **05 s1.2 item 1 (token renewal).** The text says the token is renewed "if two tile requests are refused". The mechanism is per request: one retry on 401 or 403, renewing the token only if the stored token differs from the one that failed; a renewal in flight is shared. Count is not two.
7. **05 s1.5 (viewer).** Add that all stock widgets and the default base layer are disabled (NAV-56) and that fog's "renderable" flag, not "enabled", is what the Metal workaround clears (so tile level-of-detail scaling keeps seeing fog density).
8. **02 (shortcuts).** State explicitly that there is no keyboard zoom or pan (G8) and that Q/W/E/R/T are conditional on an open landmark row.
9. **05 s5 / 06 (lighting).** State that there is no sun-driven day/night shading (NAV-66).
10. **06 s1.4 (tilt).** Confirms 650 ms and thresholds; add the heading fallback when pitch is within 1.5 degrees of straight down (target-frame heading is undefined there).
