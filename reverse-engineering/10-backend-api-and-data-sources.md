# 10 - Backend API and Data Sources (behavioural reverse-engineering)

**Purpose.** The reference product is a browser globe backed by a small, local server that acts as a "key broker" and polite caching proxy in front of dozens of public and keyed data providers. This document describes what that server is responsible for, every capability it exposes (grouped by purpose, not by address), its caching, throttling and fallback behaviour, every upstream data source with its key requirement and licence/terms notes, the data that ships inside the application, and how health and setup status are reported. It is written for a clean-room team that needs to rebuild an equivalent backend for a UAE city-intelligence product. No code, route names, file names or environment-variable names are reproduced; provider names, licence names and numeric limits are. Licence statements are reported as the reference documentation states them and are **not independently verified** - every one needs legal review before reuse. Confidence tags used below: [OBSERVED-IN-SOURCE] read from the server or client code, [FROM-TESTS] backed by a unit test, [FROM-DOCS-ONLY] stated only in the reference's documentation, [INFERRED] my reading. Unless a section says otherwise, numeric limits and cadences are [OBSERVED-IN-SOURCE] and were re-checked in this revision; licence and terms text is [FROM-DOCS-ONLY]. Mechanism detail beyond this document: 13a section 1 (geocoder chain), 13b section 1 (flight feed, credit governor, fallback), 13c section 2 (vessels and orbits), 13d (ground data sources and proxies), 13f part 1 sections 1K and 1M (server, security headers, build).

## 1. Server responsibilities

1. **Hold every secret-bearing credential** (voice/LLM key, ship-feed key, flight OAuth secret, fire-data key, traffic key, optional separate server-side maps key, optional higher-allowance launch token) and never send it to the browser. Where the browser needs something derived from a secret, the server mints a short-lived scoped token (voice) or answers same-origin requests itself.
2. **Deliberately client-visible keys** (three only, because the vendors design them for browser use): the maps key, the 3D-globe-streaming token and the street-imagery client token. They are injected into the browser build through an explicit allow-list so nothing else can leak; operators are told to restrict them at the vendor (HTTP referrer, API allow-list, URL scope).
3. **Hold long-lived upstream connections** the browser should not own - e.g. a single persistent websocket to the ship-position feed whose contents live in a server cache and are exposed as a polled snapshot (default poll 60 s from the browser).
4. **Normalise heterogeneous upstream formats** into a few uniform shapes: binary transit protobufs decoded server-side; gridded weather files (GRIB) read by byte range and resampled to a coarse display grid; ArcGIS / Socrata / GeoJSON / DATEX / bespoke JSON camera catalogues unified into one camera record with provenance, attribution and per-camera heading confidence; vector-tile and WMS imagery handling.
5. **Protect upstream providers and the operator's quota**: cache, coalesce identical in-flight requests, per-client throttles, back-off after failures, serve stale data during outages, daily budget governors.
6. **Prevent open-relay abuse** (section 4): clients almost never supply upstream URLs (the single exception is the bike-share relay, which accepts a full address but only for a fixed operator allow-list and two fixed document names), redirects are refused or validated, destinations are allow-listed.
7. **Report source health** honestly: each feed is live, degraded, stale, empty, loading, fallback or unavailable, and the UI keeps these distinct.
8. **Serve the application** (development/preview server): front-end bundle, security headers, and the same tool surface to external AI assistants over loopback.
9. **Write the user's keys on request** (local-only "Provider Settings") and restart itself.

Posture: local-first, single-user, **not** a hardened multi-tenant production service; exposure beyond localhost requires a separately reviewed authentication proxy.

## 2. Capabilities by purpose

All are same-origin, read-mostly JSON (or binary tile/image/stream) capabilities. Unknown API paths return a structured JSON "unknown route" 404 (never the front-end page). Errors are sanitised: no internal detail, no upstream error text.

**Feed-state contract between server and browser** (13b G-09). The browser learns the source name, coverage text, count, auth mode and reason, cache status and cache age from response metadata, not from the body. A fallback response names itself (source, coverage such as a 250 nautical-mile regional fallback, count) so the UI can say "regional fallback". Freshness is taken from the source snapshot's own timestamp, not from when the browser received a cached success: a snapshot older than 2 minutes, or with no time, is stale; the layer backs off, shows "Source snapshot N min old" (minimum 2) and marks every contact stale. A cold start into a rate limit with nothing cached makes the server synthesise the 429 locally; when the provider states no retry time the cooldown is 2 minutes. The regional fallback also adds the ADS-B emergency field that the primary feed lacks. In the reference walkthrough the fallback showed about 250 aircraft near Dubai and about 830 near London [FROM-DOCS-ONLY]; one count only, so Gulf community-receiver coverage is [UNVERIFIED]. Mechanism detail: 13b section 1.1.

**Navigation-integrity cell algorithm in one place** (13b G-04). Per aircraft: airborne, position from direct broadcast or multilateration, broadcast version 1 or 2, position age 0-60 s, derived quality values ignored; degraded when accuracy category is below 8, or containment category below 7 (except containment 0 with accuracy 10 or better, treated as unknown), or the aggregator's GPS-lost flag is set (the evidence then sits at the last good position). Per cell (0.5 degree square): an aircraft counts once per cell per 30-minute window; presence and degraded evidence age separately, so a degraded report keeps that aircraft degraded for a full window however many healthy reports follow, and a recovered aircraft is not held degraded forever. Rows are dated by when the proxy observed the snapshot, so replaying a cache never restarts a window and a snapshot older than the window adds nothing. Score 100 x max(0, degraded - 1) / total; cells with fewer than 3 aircraft are hidden; low under 2 percent, medium 2-10, high over 10; fill alpha 0.30 / 0.42 / 0.55; cells are not pickable (a ground primitive with picking disabled still erases picks of overlapping geometry, so a render-only fill is used). **Mobility mechanism notes (13d).** (a) *Flow-to-road snapping.* Flow lines and map roads share no identifiers, so flow is attached geometrically: each flow line is split into short pieces filed into a grid of about 100 m cells by midpoint; each map road is sampled at up to 7 evenly spaced points; for each sample the nearest flow piece within 35 m counts only if its compass direction is within 30 degrees of the road's travel direction (two-way roads are two travel directions, each matched alone; a flow line flagged as covering both directions may match either). A road is matched if at least half its samples (minimum two) matched; its congestion value is the median of matched samples (resists one wrong piece); it is closed if any matched piece is closed. Output per road is a level 0-1 and a closure flag, or "no flow". (b) *Hybrid de-duplication.* TomTom roads are drawn wherever TomTom has them; a map road survives only where TomTom has none, tested by sampling every 10 m for a TomTom line within 35 m (15 m when exactly one of the pair is a controlled-access mainline, so frontage and service roads 20-40 m from a freeway survive); partly covered roads keep only uncovered stretches of at least 40 m. Only real drivable TomTom categories (motorway through minor local) become vehicles or suppress map roads; unknown, private, parking and walking categories never do. (c) *Transit mode inference.* A vehicle's mode comes from its route identifier using operator conventions (Boston: colour-named lines are rapid transit, an express-rail prefix is commuter rail, a boat prefix is ferry, numbers are buses; Norway: operator codespace; Helsinki: leading digits, a 10xx range for trams, an M suffix for metro, 1019 for ferry), falling back to the feed default; a defaulted mode is flagged inferred and the permissive 200 km/h plausibility ceiling applies. Each stored position records where its timestamp came from (vehicle clock, feed header clock or time of receipt). Playback lag is learned per feed (95th percentile of report lateness plus 5 s, floor 25 s, reset after 90 s of feed silence). Transit feed registry admission rule: keyless, open licence, real coordinates, with each feed's default-enabled decision recorded alongside the terms passage. Fleet cap 15,000. (d) *Failure honesty:* key missing 503, budget 429, upstream 502/504; road-tile rate-limited, timed-out or unavailable states are reported distinctly. Kawn: no UAE equivalent exists in the reference, so RTA/ITC feeds and a UAE traffic licence are needed; the built-in camera seed list covers eight cities including Dubai (see 2.6).

### 2.7 Places, geocoding, map data

**The typed-search geocoder chain** (13a section 1.3, NAV-09 to NAV-15, G1-G4). Mostly browser-side orchestration with one server hop; six providers are tried in order and the first that returns a place wins: (1) decimal coordinates, offline and exact; (2) bundled names, offline and exact (nine city names and 45 landmark names, compared after case, accent and punctuation folding; whole-name matches only, so a bundled name never shadows a real geocoder); (3) the unqualified Alps outline, offline; (4) Google Geocoding, only if a browser Google key exists, with the current view box passed as a bias; (5) Photon, keyless, biased to the view centre; (6) the app's own Nominatim proxy as last resort. (Three of the six are offline steps; only Google, Photon and the Nominatim proxy touch the network.) The whole chain has a 12-second budget; caller cancellation aborts it; the result records whether a fallback was used. **Caching:** definitive answers (a place, or a clean "nothing found") are cached 5 minutes (30 seconds for "nothing"), most recent 64 queries per view bias; a timeout or network failure is never cached, so a transient outage cannot be remembered as "no such place". Every provider's result is translated into one place shape (position, label, Google-style type list, an "exact, do not second-guess" flag, optional viewport box) so framing logic is written once.
- *Photon adapter:* asks for five candidates (proximity bias reorders them); pass one is biased to the view centre only (Photon takes a point, not a box) and accepts a candidate only if its folded name equals the query or begins with it; pass two is unbiased and prefers a name equal to or starting with the first comma-part of the query, then one containing it, else the first. Any candidate that is not a valid point invalidates the whole response. 6 s timeout; hits memoised 5 minutes, definitive misses 30 s, 64 entries. Type inference uses place tags first (parks, stadiums, universities, airports, malls, zoos, theme parks, cemeteries, forests, regions, suburbs; town squares deliberately precise; natural, water and land-use keys are natural features; a highway is a street) and only then Photon's coarse class. The reason: a lake or park with no area type was framed at building range, while a town square treated as a locality framed like a city. A box with west greater than east (date-line wrap) is dropped and the place framed at its point.
- *Nominatim proxy:* whether the local proxy uses the bounds bias it is sent is [UNVERIFIED].
- *Administrative-box sanity gate:* a city or state box whose diagonal exceeds 300 km is discarded when the geocoder's anchor lies more than 15 percent of the diagonal from the box centre, replaced by a 40 km square around the anchor (countries and explicit overview requests exempt). **Kawn:** emirate-level boxes (Abu Dhabi emirate includes large desert and offshore areas) are likely to trip the same flaw; test "Abu Dhabi", "Dubai" and "Sharjah".
- *Coordinate grammar:* exactly two decimal components separated by comma, semicolon or whitespace, at most one hemisphere letter each (letters may reorder the pair if they name different axes); no degrees-minutes-seconds, UTM, MGRS or plus codes; result gets a 0.03 degree box.
- *Nearby-place recovery:* if the answer is not exact and a Places service exists, and the geocode is missing or more than 50 km from the view centre, a Places text search biased to a 6 km circle is tried and trusted only within 8 km of the view centre. Without a Google key this step does nothing.
- *Kawn:* replace the public Photon and OSM proxies with licensed or self-hosted services; add a Gulf-aware provider and Arabic handling; Arabic-script and bilingual queries on Photon and Nominatim are [UNVERIFIED].

**Google 3D tile access token** (13a NAV-43 to NAV-45; correction to doc 05). When the browser has no Google key, the server issues short-lived Google access tokens (value plus expiry). The browser caches the token, renews it one minute before expiry, and shares one in-flight renewal among callers. This is per request; it is not a count of two refused requests. Startup order: direct Google tiles with a browser key, else server-issued tokens, then the ion-hosted copy of the same dataset if an ion token exists; first success wins. ### 2.10 Assistant protocol (MCP) and panel
Local stdio and loopback-only HTTP tool endpoint, plus a panel build served from the same server and a panel-only relay. Details in doc 08 section 9. Relay specifics (13f GAP-5, SYS-093 to SYS-096): a host that blocks localhost cannot let the panel reach the app server, so a panel-only tool, hidden from model listings by an app-only visibility flag, relays any app path through the assistant server; every call must carry the per-server key embedded in the panel page (a routing guard, not access control). Large responses are compressed and sent in parts that the panel reassembles; continuation state lives in the one server process, so consecutive calls must reach the same process. Path refusals are normalised before matching (letter case, percent-encoding, trailing-dot tricks) and cover setup, credential, model, assistant-protocol and dev-server internals. Stdio processes of one install share a key file at a fixed location in the checkout cache: creation is atomic, a malformed file triggers a repair where exactly one process wins, a busy repair waits at most 2 s and then each process falls back to its own key and logs that panels may fail across processes; an abandoned repair lock needs manual removal after confirming no repair is running; HTTP servers keep per-server keys. Host quirks handled inside the panel only: images and stylesheets delivered as data URLs (some hosts refuse blob images), an https base address supplied for code that needs one, drawing driven by a timer when the host reports the panel hidden, and 2D canvases kept in memory so a host that treats the panel as off-screen cannot blank overlays. Tool error classes: invalid arguments, unavailable, unsupported, malformed, retry later; others reported without detail; string lengths counted in Unicode code points. Voice sessions and the shared tool catalogue share one tool-name namespace with browser actions taking precedence (13f GAP-2). Kawn: replace the relay key with real authentication in its own hosted assistant server.

## 4. Request gating, SSRF defence and abuse control

- **Loopback bind by default.** LAN exposure is an explicit opt-in (with a launcher warning). The launcher refuses its own tunnel/LAN sharing.
- **Host-header allow-list** applied before any route, in every mode (blunts DNS rebinding). When bound to all interfaces: IP addresses, localhost and explicitly listed names only; wildcard and suffix entries ignored; local-network ".local" names are not trusted by default. The broker is one middleware set with about 65 distinct capability paths in front of the whole key-bearing surface (aircraft, military, vessels, tracks, satellites, launches, weather, wind, cyclones, perimeters, GNSS, traffic, transit, bikes, cameras, radio, places, geocode, route, terrain, regional brief, setup, realtime, HUD summary, local receivers, street imagery). Per-IP and global limits are independent per family (for example installations are not covered by the general map-feature limiter); concurrency limits and in-flight coalescing apply on top.
- **Cross-site gate** applied only to: the voice session credential, the HUD summary, the ChatGPT-login status and start, the voice debug-log sink, the two Google Places lookups, and the street-imagery status and coverage tiles. It refuses a foreign or opaque Origin, fetch-site metadata other than same-origin/none (catches images/navigations without an Origin), and any reverse-proxy/CDN forwarding header. Non-browser local tools without Origin keep working. **Not gated** [OBSERVED-IN-SOURCE]: flights, ships, traffic tiles, fires, routing, geocoding, camera, transit and every other proxy, so a hostile web page in the user's browser can still make the local server spend traffic, fire or OpenSky quota (the Host allow-list and loopback bind are the only protection there). [INFERRED: a cross-site page cannot read the replies without CORS, but can trigger the fetch.]
- **Stricter loopback-only admission** for Provider Settings and the ChatGPT-login path.
- **No client-supplied upstream URLs, with two narrow exceptions.** Cameras, transit feeds and receivers resolve from server registries by id; other proxies target fixed hosts; redirects refused or manually followed with per-hop origin checks and no scheme downgrade. Exceptions: (1) the bike-share relay accepts a full https address but only on its operator host allow-list and only for the two station documents; (2) the detailed-map-feature relay accepts a query body from the browser, but only against operator-configured upstream servers, with size, selector and area limits (section 2.7); satellite-element group and ship id are validated strings that go into a fixed address.
- **Radio directory** resolves DNS itself, rejects loopback/private/link-local/metadata/non-global answers (v4 and v6), allow-lists hosts and paths, pins TLS to the validated address and returns only public HTTPS stream targets.
- **Local receiver URLs**: loopback/private/localhost/.local only, required file ending, no credentials/query/fragment; invalid entries logged at start and never fetched.
- **Headers**: only a canonical single byte-range is ever forwarded; others dropped.
- **Cancellation**: abandoned client requests cancel upstream.
- **Throttles**: per-IP per-minute guards (voice/HUD 30; Places 120; debug log 120/400; routing 60/200; overpass and installations 90/300; street tiles 600), in-memory and per-process; zero disables; unreadable value falls back to the default; **not billing caps**.
- **Caps**: bounded bodies everywhere (typically 2-32 MB; larger only for video ranges), short timeouts, row caps, entity-count ceilings.
- **Headers/CSP** [OBSERVED-IN-SOURCE]: framing denied by default on every document with both the frame-denial header and a frame-ancestors none directive (an allow-list of ancestors, or any, applies to embed-mode documents only; the assistant panel needs no framing); no inline scripts; frame sources limited to the embedded media players; content-type sniffing off; content-security policy with scripts limited to the app itself, blob workers, the maps script host and the YouTube, Facebook and X hosts used only by the Nepal scene; styles allow inline plus Google Fonts; images, media and connections allow any https origin (connections also allow websocket schemes) because of the provider count; no plugins; base address and form targets locked to self. Two documented accepted weaknesses: an eval allowance required by a bundled UI library; a trusted maps script host with legacy callback endpoints.
- **Local CLI spawn**: the ChatGPT-login start action launches the vendor's command-line sign-in tool with a scrubbed environment (no provider keys), one attempt at a time, cancelled after two minutes or on server stop; the credential file written by that tool is read but never written or refreshed by the app. [FROM-DOCS-ONLY]
- **Error hygiene**: sanitised errors; voice log redaction; navigation-integrity proxy strips identity; local receiver responses name feeds by band only.

## 9. Server build, run and deploy shape (13f section 1K/1M)

- **Build tool and plugin order.** No front-end framework. The bundler runs plugins in a fixed order: host-header check first, the 3D-engine bundler, HTML templating, the provider middleware (the broker), embed-framing headers, then the panel build. The production build uses a separate cache directory so a running development server's optimised modules are not cleaned; some radio, geoid and street-image modules are pre-bundled at start to avoid "outdated optimised dependency" 504 errors in development.
- **Panel build.** A separate bundle (one script, one stylesheet, the engine script carrying its workers from memory) served at a panel path from the same server; it must be rebuilt after app changes; first load 10-20 s (doc 08 section 9).
- **Preview versus production.** The preview server serves the built front-end and the same provider capabilities; it "is not a production server". Provider Settings and setup routes exist only in development. Browser-visible keys are baked in at build time, so a key change needs a rebuild. Unknown API paths answer a structured JSON 404. Dependency baseline: Node 24.14 or 26.
- **Launch shapes** (doc 11 section 8): one-click installer, terminal path, recommended macOS launcher with shell > environment file > Keychain precedence, production preview, assistant transports.
- **Kawn:** do not reuse the dev-server-as-backend shape; keep the capability contract (broker, caching, gating) in a proper hardened service; keep the idea of a separate panel bundle only if an assistant-hosted panel is built.
