# 13f - Feature census: voice, tools/MCP, HUD, detection, looks, first-run, keys, platform, and the orphan hunt (prefix SYS)

Clean-room note: behaviour and technique only. No code, no file/function/variable/route/env-var names. Public standards, provider names and numeric
behaviour values are named on purpose. Top-level folder names and documentation titles appear only in the orphan hunt (Part 2), because that is the job there.

Status of this file: written in stages (Part 1 = feature census, Part 2 = orphan hunt, Part 3 = gaps/corrections/unverified). If an interruption left a
later part missing, Part 1 is still complete on its own.

## Purpose and method

Independent enumeration of the original app's voice agent, tool catalogue and MCP server, point-and-ask, analyst answers, HUD and intel summary, detection
overlay and label placement, scope/feather, visual looks and shaders, bloom/sharpen, first-run, settings/keys, cost metering, embed mode, credits, error/status
systems, server/proxy, test/QA tooling and build/deploy (including the one-click installer), done BEFORE reading our docs, then compared with docs 00-12,
specs 01-04 and docs/05, then an orphan hunt over every top-level folder, every GitNexus community and process, and every documentation file in the original.

What was read: the original's README, changelog (all 1,789 lines scanned for removed/retired/planned items), known-issues file, the 21 documents in its docs folder
(current-state reference read in the voice, UI-defaults, security and auth sections), the voice, tools, HUD, style, scope, first-run, key-setup, embed, build and
installer sources, the voice-routing benchmark harness, the CI definition and the test guide.

GitNexus queries run (all small, none repeated): the repository list (code-graph index of the original: about 1,800 files, 31,000 symbols, 300 processes);
a Cypher listing of all 300 processes ordered by step count; a Cypher listing of all communities with label and symbol count (1,395 with two or more symbols,
grouped into 122 label families); and a membership query on the unlabeled "Cluster_N" communities to learn which root-level source files they hold. Process labels are
auto-generated "entry point to deepest callee" chains and carry no feature names; they were mapped by entry-point family (Part 2.3). Source was then read directly.

Verdict legend: DOCUMENTED (doc + section) / THIN (mentioned, missing detail needed to rebuild) / MISSING. Kawn verdict: KEEP / ADAPT / LATER / SKIP.
Numbering of docs: 01 UI, 02 keys+share state, 03 movement layers, 04 infra/weather/cameras, 05 looks/rendering, 06 camera/cockpit/contacts, 07 HUD/detection/scope/annotations,
08 voice/tools, 09 director/scenes, 10 backend, 11 config/keys/costs/privacy, 12 external URLs; specs 01-04; docs/05 inventory.

Headline: the existing docs are already very deep in this domain (voice, HUD, detection, looks and platform are each covered at rebuild level). The census therefore finds
few MISSING items; the real value is the THIN list and the five corrections in Part 3, plus the orphan map showing that everything in the original maps to a documented
feature except a short list of developer-only, marketing and tooling items.

## 3.1 Gaps found (THIN or MISSING), each written out so it can be filled now

Count: 4 MISSING-or-near-missing items, 10 THIN items (list below). Everything else in Part 1 is DOCUMENTED at rebuild level.

**GAP-1 (THIN, SYS-023): the voice-routing benchmark.** Doc 11 mentions only a developer-only benchmark host. Full behaviour: a command-line harness measures how reliably a speech/LLM provider picks the right tool for a spoken phrase, with NO app page involved. It sends every provider the production instructions and the production tool schemas (for OpenAI Realtime it uses the exact session body the token route would mint), a fresh context per phrase, stubbed tool results, and up to four continuation rounds until the model stops calling tools. Providers: OpenAI Realtime, Gemini Live (native-audio model that rejects text output, so the harness requests audio and bills the spoken confirmation at the audio-output rate), a local model runtime, and any OpenAI-compatible chat endpoint. Four suites: core (the routing phrase table with semantic grading plus typed-argument checks), coverage (probes for the newer layers, each row graded correct / honest-refusal / hallucinated-capability / wrong-tool, graded twice: an original rubric against the original tool schema and a second rubric for the current schema), dialogue (two-turn exchanges where turn two depends on turn one, e.g. a follow-up filter), and capability (area handles, imagery, map data, and point-and-ask phrases). Flags: output folder reusable to collect several models, suite and phrase filters, a total cloud-spend budget, temperature, context size, a reasoning toggle for local models, and a summarise mode. Cost uses the app's own rate table; unknown OpenAI model ids resolve to the priciest known table; Gemini rates carry a verified-on date; unattributed tokens bill as audio (the conservative direction for a cap). Kawn use: run the same harness on candidate Arabic/English models; add Arabic, Gulf-dialect and code-switched phrase rows; keep the honest-refusal grade because it measures the failure the product forbids (claiming a capability that does not exist).

**GAP-2 (THIN, SYS-080/083): how the shared catalogue composes, and how voice joins it.** Voice sessions list the 30 browser actions first, then append the catalogue's function-style tools, skipping any name an action already uses (so the action for satellite passes wins over the catalogue's version). The browser does not load the catalogue at start: the first time voice calls a non-action tool, the page builds the services over its own fetch and composes the catalogue, then routes by name - action names to the action runner, everything else to the catalogue, passing the call's abort signal so a barge-in cancels in-flight lookups. Results are converted to {ok, tool, summary, data}; image results are not sent to voice, only counted. Catalogue rules: a tool is dropped if any service it requires is absent (so a deployment without a places key simply has no place search, and combined briefs mark those sections unavailable); a name clash fails unless declared a replacement; call interceptors run outermost-first and see composite sub-calls tagged with the parent tool.

**GAP-3 (THIN, SYS-047): one manifest drives voice reach.** A single plain-data manifest lists every layer with its spoken aliases, and separately whether it can be toggled by voice, can register in-view context, can be tracked, and which analyst fields (with type and unit) it exposes - or why it has no analyst query. Both the server (to build the model's enumerations) and the browser (to resolve aliases) read it; a test fails if a catalogue layer is neither listed nor explicitly excluded. Kawn should keep this single-source rule so a new layer is voice-reachable the day it ships. Notable no-query layers: GNSS integrity (cells, not countable records).

**GAP-4 (THIN, SYS-008/010): the two ordering rules that prevent lost spend and deadlock.** (a) The cost tracker may only be swapped when the session is fully settled - not active AND no data channel AND no peer connection - because after an error status the transport can still deliver a late completion carrying usage; swapping earlier loses that spend or lets repeated tier toggles dodge the cap. (b) Every tool call must be answered once, even refused ones: a call from a superseded response gets a terminal "superseded" output, because an unanswered call leaves the conversation waiting and deadlocks the model; the refusal itself must not trigger a new response.

**GAP-5 (THIN, SYS-094/095): MCP globe-panel relay details.** The relay tool is hidden from model listings by an app-only visibility flag, requires the key embedded in the panel page, and answers large responses compressed and split into parts that the panel reassembles; continuation state lives in the one server process, so consecutive calls must reach the same process. Path refusals are normalised before matching (letter case, percent-encoding, dot suffix tricks) and cover setup, credential, model, MCP and dev-server internals. Stdio processes of one install share a key file at a fixed location under the checkout cache: creation is atomic; a malformed file triggers a repair where exactly one process wins; a busy repair waits at most 2 s then each process falls back to its own key and logs that panels may fail across processes; an abandoned repair lock needs manual removal after confirming no repair is running. HTTP MCP servers keep per-server keys. Host quirks handled inside the panel only: images and stylesheets delivered as data URLs (some hosts refuse blob images), an https base address supplied for code that needs one, drawing driven by a timer when the host reports the panel hidden, and 2D canvases kept in memory so a host that treats the panel as off-screen cannot blank the overlays. Kawn's own hosted MCP should replace this with real authentication.

**GAP-6 (THIN, SYS-127): detection costs nothing when idle - five rules to copy.** Detection repaints on change and asks the frame governor for exactly one more frame only while spanning work is outstanding; every outstanding-work predicate must terminate (enable fade-in, label fades in both directions, an unrun solve); paint and demand read the same monotonic frame timestamp, never a wall clock; a skipped paint defers, never cancels, from one shared decision; a changed detectable set (layer tick or visibility change) marks the solve dirty without itself requesting a frame. Coupling to keep: aircraft brackets stay prompt only because the aircraft layers themselves hold the render loop - strip those holds and bracket promptness disappears silently.

**GAP-7 (THIN, SYS-172): iOS/iPadOS rendering workaround.** See the row: the model-atmosphere stage is disabled on devices whose driver cannot link it, via a throwaway WebGL2 probe with platform detection as backstop; cost is loss of distance fog on 3D tiles and on keyless/Esri/Bing basemaps there. Needed for any Kawn iPad support.

**GAP-8 (THIN, SYS-015): speech lint rules.** A pure checker flags hedge phrases and "approximately" before an exact tool number, counts spoken words versus answer words per turn, and feeds the per-turn span record; used by QA and by benchmark grading to keep replies short and exact.

**GAP-9 (MISSING, SYS-227): offline imagery tools.** Not product features. Technique worth recording: stitch the provider's satellite tiles at a chosen zoom (about 6.4 cm per pixel at zoom 21, 3.7 cm at 22) into a square ortho image centred on a point and report GSD, ground coverage and corner coordinates for georeferencing; fetch 8 compass-heading street images at a point, optionally walking first-order neighbours with de-duplication; reproject a panorama to pinhole views; render a 3D-engine capture headlessly. Useful for building ground truth for Kawn's UAE camera-pose calibration.

**GAP-10 (THIN): panel surface contract and package export map.** Panel contract: a new panel declares theme tokens, receives rail input, and has a fixed header with a bounded scrolling body; owners keep disclosure, persistence and placement; known limit is popup clipping in the small-screen rail. Export map: portable modules (infrastructure, application, view, tool catalogue and MCP, source factories, selected server providers, bundler config) are separately importable and are checked by a boundary test to stay free of DOM, engine and Node-only imports - the reason the same tool code runs in browser, server and tests.
