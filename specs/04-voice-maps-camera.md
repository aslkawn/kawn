# 04 - Voice, Maps, Camera: Behavioral Specification

Clean-room behavioral description of a reference web app that shows a photorealistic 3D globe with live data layers and a hands-free voice assistant. It describes observable behavior and intent only. Detail lives in reverse-engineering docs 05 to 09; pointers are given per section.

## 1. Voice sessions (user view)

Detail: reverse-engineering/08 sections 2, 3, 7, 8.

**Starting.** The user clicks a mic control and grants microphone permission. A click-started session is open-mic: the assistant listens continuously and the cloud service detects the end of each utterance; Space never mutes it. Alternatively the user holds Space for 500 ms to claim push-to-talk: it starts a session if idle, the mic is open only while held, and on release the mic is muted but the connection stays up so the reply plays. Arbitration: a shorter tap keeps its normal job; Space in text-entry surfaces or with modifier keys is never claimed; Space on the map canvas is reserved for voice; changing focus or hiding the tab abandons a pending hold. Level meters show input and output (the input meter uses a stricter threshold because room noise leaks through). Status words: off, connecting, listening, executing, error.

**Backend.** Cloud speech-to-speech over a direct browser-to-provider real-time connection; audio never passes through the app's own server. The browser holds only a short-lived one-time secret minted by a local server (30 s server timeout, per-client throttle of 30 requests a minute); the long-lived credential never reaches the page. Two auth modes: operator API key (default; dollar estimate, warning and cap apply) or an experimental local ChatGPT sign-in reused from the vendor's tool (loopback clients only, no dollar estimate and no cap, account-terms risk; Kawn skips it). Standard and mini model tiers are selectable; the choice applies to the next session only, and an unknown tier silently resolves to Standard. Disconnects get a 6 s grace period.

**Turns.**
- The assistant may answer in speech, run actions, or both; actions run while it talks. Instant commands get no preamble; slow multi-step work may get one sentence of at most 12 words. Several changes in one utterance ("night vision and flights on") are all called before any confirmation; a partial subset is never confirmed and failures are named.
- Silence fill is code-authored: a soft tick after about 0.7 s (only when the mic is muted, i.e. after a push-to-talk release; open-mic relies on the card's visual progress), a first spoken progress line at about 1.5 s, at most two step lines at least 3 s apart, one "still working" line at about 8 s. The tick never lasts beyond about 15 s.
- Results are composed in code: a very short spoken line (about 25 words at most, numbers exact and never "approximately", caveats such as stale, degraded, unavailable or lower bound folded in) plus a richer on-screen card, not read aloud unless the user asks why, how sure, or which source. The card keeps the last 220 caption characters, up to 6 steps and 6 detail lines, and at most 5 numbered rows so the user can say "the second one"; only the latest list is addressable.
- Typed input supersedes older spoken intent: the in-flight response is marked superseded, its late tool calls get a terminal "superseded" answer and its queued follow-up is dropped. Identical tool calls within about 2.5 s are merged.
- Every tool call receives exactly one final outcome (accepted, refused, cancelled or superseded). The assistant claims success only for actions that really succeeded. Feed text (callsigns, place names) is untrusted data, never instructions.

**Interruption.** The provider's automatic interruption is off; the app itself detects the user speaking over the assistant and truncates the reply to what was actually heard. A claimed push-to-talk hold also stops playback, except during a radio handoff. Superseded responses are tracked so late audio or tool calls cannot affect the new turn.

**Radio handoff.** The assistant first speaks a short confirmation ("turning on the radio", never "it is playing"), the radio is held muted, and only after voice playback is verified quiet does the station start. Starting a voice reply or holding Space silences the radio.

**Point-and-ask.** Detail: reverse-engineering/08 section 2.8. The pointer is tracked over the globe only; hovering still (under 12 px for 250 ms) lazily picks the nearest entity, else a ground point. A pick counts only while fresh (over the map, 8 px from the edge, moved within 30 s). A reticle ring shows what was understood and disappears on any camera move, 1.5 s after the reply, or after 10 s at most; the card shows a "THIS: label" or "HERE: lat, lon" chip. The pick used is the snapshot taken when the user decided to ask (key-down for push-to-talk; recent pointer for open-mic). "This", "here", "that plane", "around here" make the model pass a "pointer" marker or list index and the app fills in the real target, or returns a plain error sentence if nothing was under the cursor; the model never copies coordinates. For ground picks "around here" is a radius of three quarters of camera height, in whole kilometres clamped to 5-400 km (50 km if unknown).

**Visual grounding.** On demand at street-level scale, a screenshot is downscaled to about 1 megapixel and sent only if the encoded size is under 200 KB and the frame is fresh and not almost black. One image is retained at a time; the assistant is told not to invent labels. The capture includes anything on screen (camera feeds, imported files).

**Context.** The conversation window is deliberately short (about 3,000 tokens after instructions); before location questions the assistant fetches live scene state (coordinates, view scale, street, active layers, selected entity).

**Cost controls.** Detail: reverse-engineering/08 section 7. A running estimate is shown (a trailing asterisk marks an incomplete estimate). Usage per response is summed, cached tokens use the cheaper rate, rates come from the model the server actually used, unknown models are priced at the most expensive known rate, and missing usage detail is attributed to audio so estimates err high; caption transcription is metered separately. Rates verified 18 Aug 2026 (flagged verify-at-release), USD per million tokens: Standard text 4 in / 24 out, audio 32 in / 64 out, image 5 in; Mini text 0.6 / 2.4, audio 10 / 20, image 0.8 (cached rates are about a tenth, audio-cached lower still). Transcription runs 1.25-10 per million tokens or 0.006 per minute. Soft warning at $2 (amber readout, one log line, session continues). Hard cap at $5: session closes through the normal stop path, no new tool dispatches after it trips, running tools finish with no rollback. Either can be disabled and stays disabled across reloads; a corrupt stored value falls back to defaults, never disarming the cap. They are runaway guards (hot mic, feedback loop), not a budget; the per-client minting throttle (30 a minute) is not a billing cap.

**Errors.** Failed token, offer or network steps give a plain-language message and a bounded error history (last 30); a stale startup attempt cannot leak into a replacement session; after an error with the connection alive the UI returns to listening. Stop tears down in order: invalidate pending work, close transport, stop audio analysis, release the mic, clear conversation memory. The cost cap uses the same path. Debug logs omit transcripts and tool arguments by default and redact secrets; per-turn latency spans are logged; a recorded-audio test mode covers both mic modes.

## 2. Voice-invokable actions (abstract catalogue)

Detail: reverse-engineering/08 sections 4 and 5, 9. A voice session offers **55 tools**: **30 app-control and interrogation actions** run in the browser (one of them the analyst query) plus **25 read-only world-query tools** from a shared catalogue of 40 definitions (15 switched off for voice). Arguments are strict: no extra fields, enumerations, numeric ranges, length caps. An old status line saying 28 actions is stale. Common guards: while cockpit owns the camera, camera-moving tools are refused by design and must not be retried; starting any navigation releases the previous motion owner; drawing mode owns the pointer; results carry a prepared spoken line and a card payload.

*Navigation and camera:*
- Fly to a place: preset city (eight in the reference, including Dubai), free-text query, coordinates, "pointer" or list item; close or overview framing; explicit range 100 m to 20,000 km; optional wait for arrival. Select the nearest aircraft near a place is one atomic step (fly, wait, load layer, skip grounded, follow) that does not open contacts or cockpit.
- Relative zoom (little/medium/lot); full-globe view (about 18,000 km); camera motion (orbit, pan, tilt, rotate, stop; slow/normal/fast; once or continuous; a bare "stop" stops the motion only); fly a drawn route; frame what is overhead (aircraft, ships, satellites; default radius 150 / 120 / 3,000 km).
- Track an entity by callsign, hex address, registration, ship name or MMSI, satellite name or number, "biggest fire", pointer or list item (exact matches before prefix before substring; ties break deterministically); stop tracking.

*Annotation whiteboard:* one call draws 1 to 24 marks (pin, highlight, area, arrow, route, label) at a place name, "pointer", coordinates or screen position; routes take 2-12 waypoints (walking default, driving, cycling); five colours; labels up to 120 characters; optional fly-to; non-persistent marks fade after about 20 s. Names resolve to real outlines (building footprints, districts, bundled administrative boundaries with no network call, natural regions); region-scale features never get a lone pin. Routes follow streets with distance and time; arrows speak straight-line distance; partial failures are reported honestly, direct-line fallbacks are labelled, and outlines still being traced are flagged pending. Up to 120 live marks, duplicates detected, persistent until an explicit "clear". Navigation-only requests draw nothing. See section 6.

*Console operation:*
- Toggle a data layer (aliases from one manifest so every shipped layer is reachable; replies name stale or unavailable feeds); open the layer menu without toggling; open or close a panel; context mode (off, contacts, space missions); cockpit (enter, exit, previous, next, status; filters by contact type and aircraft class).
- Visual style (seven looks); post-processing (bloom 0-200, sharpen 0-100); HUD visibility and one of four layouts; detection overlay (sparse/balanced/dense, density, allocation); sonar effect (needs the Cyber layout, never switches it as a side effect); basemap by explicit stack name (refused with the UI's reason).
- Scenes: list, play one, stop, next, status. CCTV panel and radio control (a qualified request selects a station and never moves the camera). Report current view state; transponder emergency flags are broadcasts, not confirmed incidents.

*Interrogation:*
- Entity context: selected-object properties or a shortlist of visible entities (only under about 100 km altitude; limit 1-12, default 5) plus place context assembled within 1.5 s; route and airport data read only from returned fields.
- Analyst query (count, filter, rank) over flights, ships, satellites, launches, quakes, fires, fire perimeters, cyclones, transit, bike share, plate readers, installations, datacenters and dams. Scope order: named place, explicit pointing, contacts subject or selection, then the view; no invented centres; no drawn-area scope. Limit default 12 for voice (engine 10), maximum 50. Every count names its scope in words, is spoken exactly, and says whether it is complete ("at least N" when capped); a cohort that cannot answer is "unknown", never zero; stale, degraded and unavailable feed words are spoken. "Which of those" follow-ups re-filter the last answer. A lookup alone never satisfies a follow or track command.
- Next pass of the space station or any loaded satellite (rise, peak, set; visible means sunlit satellite and observer's Sun at or below -6 degrees; weather ignored).
- The 25 world-query tools work anywhere with no layer on: launches, aircraft and ship tracks, aircraft registration, public and plate-reader camera search, radio search, place search (needs a Google key), routing, bike share, transit, traffic, weather, wind, submarine cables, the flood event pack, regional brief, cyclones, fire perimeters, terrain height, installations, map features, situation brief, military awareness. Lists default to 25 rows (max 200) and report total, returned and truncated. Camera search names partial coverage and an empty result means "the catalogue has none there"; voice receives no images.

**External assistants (MCP).** The shared definitions are also offered to outside AI assistants over a local process transport and a loopback-only HTTP endpoint (transport safety, not authentication). Exactly **30 tools** are listed, **29 model-visible** (one relay for the embedded panel is hidden from the model): 16 shared with voice, 8 area lookups that voice answers through the analyst query, 4 voice-excluded items (satellite pass, weather map image, recent satellite image, camera snapshot image), and a "show it on the globe" tool returning a shareable link and live embedded globe. Ten definitions are withheld because assistants already do them. Tools lacking a backing service or key report unavailable.

## 3. Map and imagery sources

Detail: reverse-engineering/05 section 1.

Five selectable stacks: Google photorealistic 3D, Bing aerial and Bing aerial-with-labels (both through a Cesium ion token), Esri satellite imagery (keyless), and OpenStreetMap (keyless). Behaviors:
- **Startup fallback order.** (1) Direct Google access if a Google key exists; (2) else short-lived server-issued Google tokens (renewed a minute before expiry; one renew-and-retry on an expired-token refusal); (3) then, if an ion token exists, the ion-hosted Google asset as a second attempt and the recovery path if direct access fails. If any attempt yields a tileset, photoreal 3D is the initial source. If all fail or no credential exists, the keyless globe loads and **Esri satellite is the initial source** (not a plain street map). OpenStreetMap is the last-resort safety net: if the Esri provider cannot be built, or two Esri tile requests fail, the controller switches to OSM automatically and says so; such switches are marked controller-chosen so scenes and leases can tell them from user choices. A requested source from a share link that is unavailable is replaced by the default; an unknown id resolves to photoreal.
- Only one imagery source is active at a time; switching releases the previous and shows a loading state. An unavailable chip is greyed with a tailored reason: no credentials means "add a key"; credentials present means "check restrictions, quota or network" (never tell the user to add what they already added). A failed manual switch tries the photoreal recovery source; callers must read the resulting active source, not assume success. Rapid switches are generation-counted so stale completions are ignored.
- Before/after imagery comparisons lease the map and force Esri satellite as the baseline, then restore the previous choice only if the user has not chosen something else meanwhile; one lease at a time.
- Credits follow the source actually on screen, including after fallback, and stay visible in Clean UI and presentation mode (a compliance requirement). Street-level view offers panoramic imagery as one source at a time with coverage lines, filters and legend.

## 4. Globe and terrain

Detail: reverse-engineering/05 sections 1.3 to 1.5, 3.

- True 3D globe; when photoreal tiles are active the plain globe is hidden and separate terrain is ignored on purpose (it conflicts with the mesh). Keyless terrain is an open quantized-mesh service (CC BY 4.0, attribution required); an ion token brings commercial world terrain. Terrain creation is lazy.
- Terrain throttling (429, 502, 503, 504) is retried up to 3 times with exponential backoff from 750 ms capped at 15 s plus up to 1.5 s jitter, behind one shared cooldown that honors server retry hints; other failures (outside coverage, network, abort) fall back to flat terrain promptly; cancelled requests are not retried. Under load terrain can pop in late.
- Tile cache budget 1.5 GB (up to 1 GB overflow). Sky atmosphere always on, slightly muted; fog is switched off in night-vision and thermal looks because it turns distant 3D aircraft into black silhouettes. A render governor holds continuous rendering only while a continuous camera motion, animated look or annotation needs it.
- Bloom is a 0-200 scale, default off; older share links used an inverted 0-100 scale and are converted on load. Sharpen defaults to on at 49 percent. Visual looks are screen-space filters crossfaded over 500 ms; HUD, detection overlay, annotations and panels are not filtered. Detail: reverse-engineering/05 section 2.

## 5. Camera behavior

Detail: reverse-engineering/06 sections 1 to 3.

- **One camera owner at a time.** Any deliberate navigation, manual pointer or wheel input, or new tracking takes ownership and releases the previous owner. Automatic things (arrival correction, deferred search flights, shared-link restore, ground guard) always yield to a human; a key press also stops the ground guard. Explicit navigation is refused with a toast while cockpit is active. A typed search stamps its place in line on submit but only takes the camera when its result returns, and only if still current.
- **Startup:** with no share link the view starts 25 km up looking straight down at the default city, pauses 0.5 s, then flies 4 s (cubic in-out) to 600 m altitude, heading 15, pitch -30. With a share link the camera flies 3 s to the saved pose; a user gesture during that flight cancels it. Kawn default city: Dubai.
- **Fly-to:** preset cities carry curated ground elevation, a viewport box and five landmarks, each with its own range, pitch, heading and building height for mid-height aiming. The reference's Dubai presets: Burj Khalifa (600 m range, pitch -20, heading 200), Burj Al Arab (500 m), Palm Jumeirah (1,200 m, pitch -40), Dubai Frame (400 m), Museum of the Future (350 m); ground elevation 5 m. Default flight 3 s, then a look-at lock so the target ends centred, then manual control returns. Search results pick framing by type: countries and states fly to the viewport, cities frame the viewport, natural regions use a capped oblique view, precise places use close landmark framing. Orbit key circles a landmark at 6 degrees per second.
- **Controls:** pinch is relayed as zoom with 8x gain, clamped per event. No global zoom limit in manual use; programmatic range is bounded to 100 m - 20,000 km; while following, minimum distance is 150 m. Scripted pitch is clamped between -89 and -5 degrees. Tilt toggle (650 ms) swaps between -89 and -35; north-up; reset globe flies out to 18,000 km straight down over 2.8 s keeping the continent in front.
- **Verbs:** one-shot nudges are bounded (about 30 degrees orbit, 15 tilt/rotate, a quarter of view height pan, under a second). Continuous speeds: orbit 2/6/15 degrees per second; tilt 4/10/20; pan 8/20/45 percent of view height per second. Route dolly: mean 20/40/90 m per second, about 260 m above ground, look-down 32 degrees, gaze leading by about 6.5 s, ease 2.4 s, bank up to 10 degrees, 90 m minimum clearance, maximum descent 10 m per second; reduced-motion removes the shaping.
- **Tracking:** click or voice-lock a moving aircraft, vessel or satellite. Aircraft follow camera sits behind and above (range from altitude, 3-30 km); trail 2.5 px, 85 percent opacity, up to 400 vertices, backfilled from track history; icons render about 30 s behind real time and glide. Telemetry card shows callsign, altitude (flight level from 18,000 ft), speed, route, and a stale cue. Deselect never moves the camera. At most one tracked target is stored in a share link, and the recipient's gesture cancels it.
- **Contacts and cockpit:** contacts mode shows everything within 250 km of the subject (refresh 750 ms parked, 175 ms while moving), three nearest per page, previous/focus/next with visited history, and doubles the search radius up to 16,000 km when the window is exhausted; a cohort with a down feed reports "unknown", never zero. Cockpit gives a first-person view with instruments, vision modes matching the looks, and a 12 m surface clearance. Detail: reverse-engineering/06 sections 3 and 4.
- **Ground-collision guard:** arrival framing is computed before tiles exist, so ground height is predicted (sampled height, curated city elevation, elevation service; sea level once buried the camera in elevated cities). After landing, the guard samples the rendered surface under target and camera, retrying up to 8 times, 600 ms apart; if the eye is below 120 m clearance it lifts the camera over 0.9 s holding heading and pitch; deficits of 2 m or less are ignored.
- **Escape arbitration:** Draw takes Escape first, then cockpit (one step at a time), then the credit lightbox, panels, and finally per-layer deselection; a running scene also stops on Escape.

## 5A. Director: cinematic scenes

Detail: reverse-engineering/09.

**Model.** A scene is an ordered list of shots. A shot has a camera destination (inline pose with ellipsoid height, or a scene-local named anchor plus orientation), an optional authored move (start pose plus linear or cubic ease), flight time (minimum 0.2 s, zero falls back to 4 s) and hold, both capped at 86,400 s, a visual state (style, basemap, bloom, sharpen, HUD, detection, scope), per-layer on/off states, selected data packs and up to 64 click interactions. Heights are ellipsoid-only: terrain-relative inputs are rejected and there is no collision guarantee. In a move, latitude and height interpolate linearly while longitude, heading and roll take the shortest arc (wrapping the dateline).

**Authoring and playback.** Capture shot records the live camera, visuals and every layer; update, load, next, rename and delete exist. Playback never re-establishes tracking. Each shot runs select, apply visuals, reconcile layers, travel, settle, hold, complete, with cancellation checked after every phase; a shot governs only the layers it names. Playback claims the camera, refuses to start in cockpit or during another run, and stops on Escape or any manual or voice navigation. Scrubbing and replay use the same camera sampler as live play. Presentation mode hides panels, forces the full HUD and draws a 16:9 or 9:16 safe frame; the app does not record video. Media waits are bounded so media cannot strand a scene. Projects save to browser storage after each edit and an unreadable saved project is never overwritten.

**Format and sharing.** Scene format **version 6 is current** (1-6 accepted; 4 added anchors and moves, 5 data packs, 6 interactions); a reference page still showing 5 is stale. Import previews scenes, shots, attributions and missing layers before anything changes; apply replaces the whole project; invalid files change nothing and name the failing field. Limits: 5 MiB file, 256 scenes, 10,000 shots, 1,024 anchors per scene; importing never fetches URLs or runs code. Share scene exports one scene without asset bytes; a hash-verified asset bundle (50 MiB, 64 files) must be re-imported after a page reload.

**Packs and interactions.** Up to 8 packs per scene, each with mandatory attribution and licence and optional size and SHA-256 checks: map shapes (2,000 features), PNG images up to 4096 square, audio/video markers that never autoplay. Sources are trusted app registrations only; loads carry no credentials and time out at 15 s; 8 MiB per asset, 32 MiB per shot. Interactions are declarative actions on map-shape features (text card, focus an anchor, jump to a shot, set a layer), inactive during automatic playback, keyboard-operable, never scripted, chains capped at 64.

**Bundled scenes (six, Nepal first).** Five showcase scenes of 26-36 s, 4-5 shots each: Global Flights Radar (starts mid-Atlantic), **Orbital Watch (starts over Florida and the Gulf of Mexico, about 28 N 82 W, roughly 22,000 km up)**, Thermal Threat Board, City Overload (the only 9:16 scene) and Omniscience Pullback. Plus the **Nepal Flood Incident scene of 25 shots** on a 26 Aug 2026 outburst flood: eight context-to-valley shots, then 17 evidence beats (4.2 s flights, holds up to 16 s), ending on a wide view. A fresh project seeds three legacy shots and an idempotent startup step upgrades them to 25. Honesty rules: the flood path is schematic, the 2021 image is context not a baseline, evidence counts are not independent confirmations. Its imagery and centreline are non-commercially licensed, so Kawn must not reuse them.

## 6. Annotations and Draw

Detail: reverse-engineering/07 section 5.

Voice marks and the manual Draw tool feed one annotation engine, so they persist, de-duplicate, list and clear identically.
- **Draw tool:** shapes Area, Line, Pin; label up to 120 characters; same five colours. It owns the pointer while on (selection and double-click-to-track suspend). Click adds vertices on the real surface; double-click or Enter finishes; Backspace removes the last vertex. **Escape is two steps:** with at least one vertex placed it discards the shape in progress and stays in Draw with a fresh empty shape of the same kind; with nothing placed it leaves Draw mode. Finished marks are never touched by Escape, and Escape is consumed so nothing else reacts. Minimum vertices: area 3, line 2, pin 1; maximum 512; clicks within 0.5 m merge; degenerate shapes are rejected with a plain hint. Live readout: line length (metres below 1 km), area in square metres, hectares or square kilometres. Hand-drawn lines record length, never travel time, and hand-drawn marks never trigger the camera assist.
- **Engine:** pin, area, route, arrow, label. At most 120 live marks; persistent by default, otherwise 22 s then a 1.2 s fade. Areas and routes drape on 3D tiles; pins, arrows and captions are an overlay re-projected every frame, culled behind the horizon. Route waypoints must all resolve or the call fails naming the missing ones; if routing is unavailable a labelled direct line with no travel time is drawn. Camera assist (voice only): if no new mark is on screen the camera frames them (1.6 s), never when any is visible, never on an outline upgrade, and stands down 2.6 s afterwards.
- **Import:** GeoJSON, KML, KMZ, GPX; up to 12 files, 50 MB each, session-only, read on the device.

## 7. Search and geocoding

Ordered provider chain, first definitive answer wins, each bounded (about 12 s overall):
1. Raw coordinates in several notations (offline).
2. Bundled preset names (offline), plus an offline set for unqualified Alpine names.
3. Google geocoder if configured.
4. A keyless open geocoder.
5. A local-proxied open-street-map geocoder as last resort.

Results carry latitude, longitude, display name, place types, and a bounding viewport used to frame the flight. Optional regional bias follows the current view. Definitive results (found or definitively not found) are cached with expiry; unreachable providers are not cached. Caller cancellation aborts the chain. No geocoder yields "unavailable" without network calls. Reverse geocoding supplies street and city for context. Free-text directions use a public routing service for street-following routes (drive, walk, cycle) with turn steps. The HUD also shows an optional five-word AI summary line (every 15 s, labels only, must carry a STALE, DEGRADED, FALLBACK, LOADING or UNAVAILABLE token if any layer is not nominal; falls back to a deterministic telemetry line after a 5 s timeout). Detail: reverse-engineering/07 section 2.

## 8. Offline tooling

Command-line helpers render still frames of the globe, fetch street panoramas and heading sets, reproject panoramas to flat views, and build orthographic satellite crops, for documentation and QA. Not user-facing.

## 9. Local-voice requirements

A replacement stack (local speech-to-text + local LLM + local TTS, with tool calling) must provide:

1. **Streaming STT** with voice-activity end-pointing for open-mic, plus push-to-talk (hold ~0.5 s) with exact-timing release; partial and final transcripts for the on-screen caption card.
2. **Arabic and English**, per-utterance language detection and mixed-language (code-switching) tolerance; Arabic dialects (at least Gulf, Levantine, Egyptian, plus Modern Standard); right-to-left caption display; Arabic place names and numerals (Eastern and Western digits) understood and mapped to the geocoder chain, which must accept Arabic queries and return Arabic or transliterated labels; spoken replies in the user's language with correct number, unit and distance verbalization.
3. **LLM with reliable function calling**: strict argument schemas with enumerations and numeric ranges, multiple calls per turn, parallel/ordered execution, a single final result per call, ability to refuse or cancel, and honesty (never claim success unless the tool succeeded). Must support deictic sentinels (pointer, list index) without copying coordinates, and optional image input for visual grounding or a separate local vision model.
4. **Streaming TTS** with low first-audio latency, sentence-level chunking, instant cancel for barge-in, truncation tracking (know what was actually heard), and voices in both languages. Ability to duck/mute for radio handoff and report playback-ready.
5. **Barge-in** while speaking, with echo cancellation or half-duplex fallback so the assistant does not hear itself.
6. **Progress narration** hooks during long tool runs (earcon plus bounded spoken lines; define the earcon policy for open-mic).
7. **Short rolling context** plus injection of live scene state; superseding of stale responses by newer input.
8. **Resource and cost controls**: since there is no per-token money, replace the dollar warning and cap with a time/compute budget, idle auto-stop, memory and GPU guards, model-tier selection (fast vs accurate), and clear status/error states with retry-to-listening. Keep the rule that no new tool dispatches after the guard trips.
9. **Privacy**: all audio stays on device; no credential minting needed; offline operation with graceful degradation when remote map and data feeds are unreachable.
10. **Diagnostics**: per-turn latency spans (STT, LLM first token, tool time, TTS first audio) and a bounded sanitized error log, content-free by default.
11. **Verification**: a recorded-audio test mode for both open-mic and push-to-talk to confirm mic acquire/release, tool outcome and cleanup.
